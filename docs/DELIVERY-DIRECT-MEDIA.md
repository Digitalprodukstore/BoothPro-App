# BoothPro P0 — Direct Media Delivery

This branch adds server-side delivery primitives without changing the existing kiosk flow.

## WhatsApp Cloud API

Required Vercel environment variables:

- `WHATSAPP_ACCESS_TOKEN`
- `WHATSAPP_PHONE_NUMBER_ID`
- `WHATSAPP_API_VERSION` (optional, default `v23.0`)
- `DELIVERY_ALLOWED_HOSTS` (recommended; comma-separated asset hostnames)

Endpoint:

`POST /api/delivery/whatsapp`

Body:

```json
{
  "to": "62812xxxxxxx",
  "media": [
    {"type":"image","url":"https://.../BoothPro-Final.jpg","filename":"BoothPro-Final.jpg"},
    {"type":"document","url":"https://.../BoothPro-GIF.gif","filename":"BoothPro-GIF.gif"},
    {"type":"video","url":"https://.../BoothPro-Live.mp4","filename":"BoothPro-Live.mp4"}
  ]
}
```

The endpoint deliberately sends media by HTTPS URL so the kiosk does not need to upload large binary files directly to the Vercel function.

## Email

Required Vercel environment variables:

- `RESEND_API_KEY`
- `BOOTHPRO_EMAIL_FROM`
- `DELIVERY_ALLOWED_HOSTS` (recommended)

Endpoint:

`POST /api/delivery/email`

Body:

```json
{
  "to": "customer@example.com",
  "subject": "Soft File Foto BoothPro Anda",
  "message": "Berikut soft file foto BoothPro Anda.",
  "media": [
    {"url":"https://.../BoothPro-Final.jpg","filename":"BoothPro-Final.jpg"},
    {"url":"https://.../BoothPro-GIF.gif","filename":"BoothPro-GIF.gif"},
    {"url":"https://.../BoothPro-Live.mp4","filename":"BoothPro-Live.mp4"}
  ]
}
```

The server downloads the approved HTTPS assets and attaches them directly to the email. The customer does not receive a BoothPro web link as the delivery mechanism.

## Important WhatsApp constraint

WhatsApp Business Platform policy determines whether a business may initiate a conversation with a phone number. A successful API call is not a guarantee that every unsolicited business-initiated message is deliverable; approved templates/customer-initiated conversation rules still apply.

## Current implementation boundary

The existing kiosk already publishes the final photo and GIF to Cloudinary when configured. A clean MP4/live-session asset is **not yet generated by the current kiosk engine**. Therefore this branch intentionally stops at the secure delivery API layer rather than pretending the three-media end-to-end flow is complete.

Next client-side step:

1. Generate/record the clean live video asset during the capture session.
2. Publish photo + GIF + MP4 to the configured asset storage.
3. Replace the current `wa.me` / `mailto` helper with calls to these two delivery endpoints.
4. Show per-channel delivery status and retain QR/Soft File Viewer as fallback.
